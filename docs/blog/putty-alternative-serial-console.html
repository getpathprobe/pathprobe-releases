A PuTTY Alternative for Serial Console and Network Gear

PuTTY has been the default SSH and serial client on a lot of Windows lab laptops for a long time, and for a simple SSH session it still works. The friction shows up when the same person also needs a serial console, a pile of saved sessions, and a way to talk to slow network gear without overrunning the prompt.

This article is about what to look for in a PuTTY alternative if your day includes routers, switches, and USB-serial adapters — and how JackedIN approaches those jobs on Windows, Linux, and Raspberry Pi OS 64-bit. There is no macOS build yet.

What "console work" actually needs

A terminal for network gear is doing more than opening TCP port 22.

  • Serial, not just SSH. A factory-default switch, a botched management IP, or a boot loader still needs 9600 8N1 (or whatever the vendor documents) on a COM port or /dev/ttyUSB0. The tool should list the ports that are actually present, including common USB-serial chips (FTDI, Prolific, CH340, CP210x).
  • Telnet still appears on older lab gear and on some out-of-band paths. You may not want it on a production LAN, but a console tool that refuses Telnet will leave a gap.
  • Saved sessions you can find later, in folders, with the right protocol and line settings on each one.
  • A path off the window. If you already use scripts, Ansible, or a small Python library, a CLI and a local API are more useful than a GUI-only emulator.
  • Pacing that respects the device. Many routers and switches print slowly, raise a pager, or only accept a password after a Password: prompt. A tool that dumps the next line too early will fail in ways that look like a "bad script."

None of that requires you to throw PuTTY out tomorrow. It does mean that "opens an SSH window" is a low bar.

Honest options you may already have

Plenty of capable tools sit next to PuTTY, and the right one depends on what you actually do.

  • Windows Terminal and OpenSSH are fine for SSH to a Linux box or a modern device with a stable management address. They are not a serial console for a COM port.
  • Tera Term is a long-standing free Windows emulator with SSH and serial. It is a reasonable PuTTY alternative if you want a simple window and you live on Windows.
  • MobaXterm is popular when you want many SSH tabs, an X server, and a toolbox in one Windows installer. The free edition is enough for a lot of people; serial and session layout are stronger than stock PuTTY.
  • SecureCRT is a paid, mature client with a large installed base in network teams. If your workplace already standardizes on it, an alternative has to import those sessions cleanly or it will not stick.
  • minicom, screen, or tio on Linux will drive a USB-serial adapter with no fuss. They do not try to be a session manager for SSH, Telnet, and serial together.

If one of those already fits, use it. The rest of this article is for the case where you want SSH, Telnet, and serial in one program, on Windows or Linux, with a way to import the sessions you already have.

Import the sessions you already saved

A new terminal that cannot read your old session list is a hobby, not a migration. JackedIN can import from PuTTY, SecureCRT, MobaXterm, and SSH config. A dry run is worth doing first so you can see what will come across. Passwords in an imported file are not saved (they can be offered to the vault):

jackedin import --from putty --path FILE --dry-run
jackedin import --from ssh --path FILE --dry-run
jackedin import --from securecrt --path FILE --dry-run
jackedin import --from mobaxterm --path FILE --dry-run

Leave off --dry-run when the preview looks right. After import, you should have the same hosts in the sidebar, ready to open as SSH, Telnet, or serial, instead of retyping them.

Serial console, from the window or the command line

On launch, JackedIN lists COM and tty ports and preselects an external USB-serial adapter when one is present. jackedin ports prints the same names, with the USB product name when the operating system provides it. On Windows, ports the enumerator does not report as present are omitted unless you pass --all.

A typical 9600 8N1 session on Windows, COM5:

jackedin connect --protocol serial --host COM5 --port 9600

On Linux:

jackedin connect --protocol serial --serial /dev/ttyUSB0 --baud 9600 --data-bits 8 --parity none --stop-bits 1 --flow none

--host COM5 --port 9600 and --serial /dev/ttyUSB0 --baud 9600 are the same kind of session, and --protocol serial can be left off when the host looks like a device path. A by-id path is a good idea on Linux if you plug in more than one adapter.

From the window, the status bar shows the protocol, the device, and the line settings (9600 8N1 no flow). Send Break is available from the session menu (or Ctrl+Break) when you need to interrupt a boot sequence. Session logs are cleaned into readable text — including the CR CR LF pattern a Junos console can send — without changing what you see in the live terminal.

Prompt-aware pacing for slow gear

This is the part a generic SSH client often gets wrong on real network equipment.

On a serial session, JackedIN sends a password only after a Password: prompt has gone quiet. It will not type that password at a login: prompt or at a shell prompt. A serial console also gets one carriage return after a short silence, unless you pass --no-wake, so a sleeping console has a chance to print a prompt before the first command.

For scripted commands, --line-delay waits between lines and --char-delay waits between characters. Serial exec uses a 100 ms line delay when --line-delay is omitted. Built-in profiles for Junos, Cisco IOS/NX-OS, Arista, Nokia, MikroTik and more can be selected with --vendor, or picked up from the prompt or the banner, including pager and error strings. JackedIN has been tested on real Juniper hardware.

If you are moving over from plink, the same sessions can be driven from the command line or from the local automation API, and there is an Ansible collection in the portable zip. That is a later step. Getting a reliable serial or SSH session, with pacing the device can survive, is the first one.
