Playlist: Raspberry Pi Network Lab.

  • Inline tap

    PathProbe Pro builds a transparent bridge between two 1 Gb ports. The bridge itself has no IP address, so the two devices keep talking as if they were cabled to each other.

  • 1 Gb ports

    The tap NICs are 1 Gb ports. On a Raspberry Pi, real throughput over USB is typically a few hundred Mbps, not a full gigabit. We measured 415–588 Mbps on internet downloads through the tap. That is not a LAN line-rate test. For full gigabit, use an Ubuntu PC with a dual-port Intel NIC.

  • Placed in line for testing

    The box sits on the cable between two devices so you can capture and inspect the traffic that actually crosses that link.

  • Traffic impairment Coming to PathProbe Pro

    Built-in tap impair is coming to PathProbe Pro. Today you can add delay, loss, and rate limits with Linux tc netem on the member ports, as shown in the inline tap guide.

  • Remotely managed

    The separate management port stays off the bridge. Use it for SSH, status, capture control, and a live stream into Wireshark on another computer.

What we have actually run. Our lab tap box is a Raspberry Pi 4 Model B (4 GB) on Raspberry Pi OS 64-bit, with two Amazon Basics USB 3.0 to 10/100/1000 Gigabit Ethernet adapters (model U3-GE-1P) plugged straight into the blue USB 3 ports — not a hub. We confirmed USB 3 at 5 Gbps, a gigabit link on both tap ports, DHCP passthrough, and a full DORA exchange in a PathProbe tap capture with 0 drops. Internet downloads through the tap measured 415–588 Mbps. That is not a LAN line-rate test. Current units of this adapter ship as AX88179A and use Linux's built-in cdc_ncm driver, which works but reports duplex as unknown.

The inline tap is a Pro feature and is Linux only (including Raspberry Pi). It is not in the Windows build. PathProbe Pro is $9.99 one-time and is not part of the hardware totals below. Only use a tap on a network you own or are authorized to test.

Raspberry Pi 5 (recommended if you are buying a new board)

We have not lab-tested the inline tap on a Pi 5 yet. The Pi 5 has two independent USB 3 ports and more CPU headroom, so it is the better new-buy if you do not already have a Pi 4. Use the official 27 W (5 V / 5 A) USB-C PD supply, not the Pi 4 15 W supply. Use a Pi 5 case; a Pi 4 case will not fit. Official active cooling is the right match for capture and impairment.

Ubuntu PC alternative

The same PathProbe Linux build runs on an x86 Ubuntu PC or laptop. This is the path to full gigabit: a dual-port Intel PCIe NIC is the better tap pair for line-rate in both directions: Intel I350-T2 (igb), or I210 / I226 (igb / igc). The built-in NIC, or Wi-Fi on a laptop, stays on management. A laptop used as the tap box still needs two USB NICs for the two sides of the cable.

Setup notes

  • Plug both USB adapters into the Pi's blue USB 3 ports, one per port. Do not put them on a hub. A USB 2 hub holds both adapters at 480 Mbps.
  • Leave the built-in Ethernet port for management. Do not add it to the bridge. PathProbe refuses the default-route interface unless you pass --allow-default-route.
  • Install dumpcap before the first capture (Debian and Raspberry Pi OS package wireshark-common).
  • Check the adapters: lsusb -t should show 5000M on each one. On the Amazon Basics units we use, ethtool -i shows the built-in cdc_ncm driver; for an RTL8153 alternative it should show r8152.
  • The tap NICs are 1 Gb ports, but this is not a promise of line-rate throughput on a Pi. Real throughput over USB is typically a few hundred Mbps. A Pi 4 shares one USB 3 controller between both ports, and the rate drops further when both directions are loaded, when you capture to the SD card, or when you add delay or loss. For full gigabit, use an Ubuntu PC with a dual-port Intel NIC.
  • The tap has no fail-open bypass. If the Pi loses power, the link in the middle goes down.
