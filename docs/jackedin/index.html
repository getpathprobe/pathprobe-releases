One program: GUI + CLI + API

Run jackedin with no arguments for the desktop window. Run it with a command and it stays in the terminal, prints a result, and exits — ready for scripts and pipes.

$ jackedin ports
$ jackedin connect --serial COM5 --baud 9600
$ jackedin connect --host switch.example.net --user admin
$ echo 'show version' | jackedin connect --protocol telnet --host 192.0.2.10
$ jackedin license status

Automation: why and how

JackedIN runs the same engine from the window, the command line, Python, Nornir and Ansible. Every automation feature below is built so you can see what will happen before it happens, and prove it worked after. The Python packages are free; like the terminal, they need the 3-day trial or a license. Tested on real Juniper hardware.

Dry-run

Why: see the exact commands before anything touches a device. Nothing connects and no password is sent.
How: jackedin exec --host 192.0.2.10 --dry-run --cmd 'show version', fleet --dry-run, or device.dry_run([...]) in Python.

Commit confirmed

Why: a change that cuts off your access rolls itself back instead of needing a truck roll.
How: jackedin change junos --minutes 5 prints the commit-confirmed, confirm and rollback steps. In Python, send_config_set([...], commit=True) uses configure exclusive and commit confirmed on Junos. Without commit=True nothing is committed. Cisco gets configure replace guidance.

Expect rules

Why: a run should fail when the output is wrong, not just when the connection drops.
How: a YAML file of command, expect_match and expect_no_match, passed with --expect-file checks.yml or expect= in Python.

Enable mode

Why: Cisco consoles often land at router>, and show startup-config, write or copy need privilege.
How: on the command line, add --cmd enable first and pass the secret with --enable-password-env VAR. In Python, pass enable= and the library sends enable once at the start for you. The secret never goes on the command line or into a log.

Python client

Why: network automation already speaks Python. Keep JackedIN's prompt handling, paging and login safety instead of writing your own.
How: pip install jackedin, then Jackedin("192.0.2.10").run(["show version"]). JackedinDevice has Netmiko-style send_command and send_config_set.

Nornir plugin

Why: keep your Nornir inventory and run JackedIN on every host.
How: install nornir-jackedin, then nr.run(task=jackedin_send_command, command="show version"). Tasks for config and the commit plan are included.

pytest helpers

Why: test a captured config in CI without dialing a device.
How: assert_matches(captured, rules) or the jackedin_expect fixture (needs pip install pytest).

Ansible collection

Why: keep your playbooks and inventories.
How: the jackedin.terminal collection is in the ansible/ folder of the portable zip, with jackedin_exec and jackedin_fleet. Put the password reference in JACKEDIN_CREDENTIAL, not in the playbook.

CI and unattended runs

Why: dry-run every change in a pipeline before it runs for real.
How: --accept-eula, a pre-seeded JACKEDIN_KNOWN_HOSTS, and JACKEDIN_CRED_<NAME> or a password manager (1Password, Bitwarden, Vault, OS keychain). A changed host key is always refused and a rejected password is never resent.
$ pip install jackedin
$ pip install nornir-jackedin   # optional, for Nornir
# or the same wheels from the 1.2.0 release:
$ pip install https://github.com/getpathprobe/jackedin-releases/releases/download/v1.2.0/jackedin-1.2.0-py3-none-any.whl
$ pip install https://github.com/getpathprobe/jackedin-releases/releases/download/v1.2.0/nornir_jackedin-1.2.0-py3-none-any.whl

from jackedin import Jackedin
device = Jackedin("192.0.2.10", username="netops")   # password from JACKEDIN_PASSWORD
print(device.dry_run(["show version"]).text)          # does not connect
report = device.run(["show version"], expect=[{"command": "show version", "expect_match": "Version"}])
